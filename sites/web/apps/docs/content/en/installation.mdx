KB Labs is installed through `kb-create` — a Go binary that downloads the platform, runs the setup wizard, and manages your workspace. This page covers all installation paths, version pinning, and upgrading.

## Prerequisites

- **macOS** or **Linux** (Windows support coming)
- **curl** (for the one-line install)
- **Git**
- **Node.js** 20+ and **pnpm** 9+ (installed automatically if missing, or you can pre-install)

## Quick install (recommended)

```bash
curl -fsSL https://kblabs.ru/install.sh | sh
```

The script:

1. Detects your OS and architecture
2. Downloads the correct `kb-create` binary from GitHub releases
3. Installs it to `~/.local/bin` (or `/usr/local/bin` if you have write access)
4. Verifies the binary works

After install, `kb-create` is available in your PATH.

The public `https://kblabs.ru/install.sh` URL redirects to the maintained
launcher script in the monorepo at
[`tools/kb-create/install.sh`](https://github.com/kb-labs-team/kb-labs/blob/main/tools/kb-create/install.sh).

## Pin a specific version

For reproducible CI and controlled upgrades:

```bash
curl -fsSL https://kblabs.ru/install.sh | sh -s -- --version v1.2.3
```

## Verify checksum

```bash
curl -fsSL https://github.com/kb-labs-team/kb-labs/releases/download/v1.2.3/checksums.txt \
  | grep kb-create-linux-amd64
```

Compare the SHA256 against the downloaded binary:

```bash
sha256sum ~/.local/bin/kb-create
```

## Manual binary install

For environments where `curl | sh` is restricted, download the binary directly from [GitHub releases](https://github.com/kb-labs-team/kb-labs/releases/latest):

| Platform              | Binary                   |
| --------------------- | ------------------------ |
| macOS (Apple Silicon) | `kb-create-darwin-arm64` |
| macOS (Intel)         | `kb-create-darwin-amd64` |
| Linux (x86_64)        | `kb-create-linux-amd64`  |
| Linux (ARM64)         | `kb-create-linux-arm64`  |

After downloading:

```bash
chmod +x kb-create-darwin-arm64
mv kb-create-darwin-arm64 /usr/local/bin/kb-create
```

## Bootstrap a workspace

Once `kb-create` is installed, create your first workspace:

```bash
kb-create my-project
```

The interactive wizard:

- Picks a package manager (pnpm recommended)
- Sets up the platform directory (`~/.kb` by default or project-local)
- Generates scoped `.kb/kb.config.jsonc` platform/project configuration
- Runs `pnpm install`

The declarative flow engine is available during the migration cutover:

```bash
kb-create my-project --engine
```

It renders the same scenario pages and validation for Human mode that Agents
receive through the JSON protocol. For CI, use the deterministic scoped
installer; it does not run interactive scenarios:

```bash
kb-create install --plugins=release --services=workflow --platform ./ci-platform
```

Technical compatibility is resolved from package-declared `kb.manifest`
metadata. The launcher uses the embedded catalog only for bootstrap defaults;
requirements, adapter capabilities, and provider config defaults come from the
exact package artifacts or versions being installed.

When finished, the workspace is ready:

```bash
cd my-project
kb-create status   # shows installed components and platform path
```

## Choose a release channel or version

Declarative installs can select the SDK and Platform independently. The
Platform axis always uses one release for its core packages, adapters,
services, plugins, and service companion CLI packages.

```bash
# Install the platform's canary train.
kb-create my-project --yes --platform-channel canary

# Pin a reproducible Platform release while leaving the SDK at its default.
kb-create my-project --yes --platform-version 2.118.1

# Use channels with a scoped CI install too.
kb-create install --plugins=release --sdk-channel stable --platform-channel canary
```

`stable` maps to npm's `latest` tag and `canary` maps to the npm `canary` tag.
An exact `--sdk-version` or `--platform-version` cannot be combined with the
channel flag for that same axis. `kb-create` resolves selected channels to
concrete versions before installing and stores them in the installation state.
Use `kb-create status` to see both the channel and resolved version.

If a release manifest publishes compatibility rules, kb-create validates the
resolved SDK/Platform pair before installation. It refuses an incompatible
pair without writing packages; `--force-compat` is available for deliberate
testing or recovery overrides.

## Verify the installation

```bash
kb-create status
```

Expected output:

```
KB Labs Installation

  Launcher:  kb-create v1.2.3
  Platform:  @kb-labs/cli v0.1.4
  Node:      v22.1.0
  pnpm:      9.4.0
  Config:    ./my-project/.kb/kb.config.jsonc ✓
```

If any component is missing, `kb-create status` will suggest a fix command.

## Configure LLM access

AI-powered features (Mind RAG, commit generation, AI review) require an LLM adapter. Edit `.kb/kb.config.jsonc`:

```json
{
  "platform": {
    "adapters": {
      "llm": "@kb-labs/adapters-openai"
    },
    "adapterOptions": {
      "llm": {
        "apiKey": "${OPENAI_API_KEY}"
      }
    }
  }
}
```

Set the key in your environment:

```bash
export OPENAI_API_KEY=sk-...
```

See [Configuration → kb.config](/configuration/kb-config) for all adapter options.

## Upgrading

```bash
# Upgrade kb-create to latest
curl -fsSL https://kblabs.ru/install.sh | sh

# Upgrade the platform packages inside a workspace, keeping its selected channels
cd my-project
kb-create update
```
